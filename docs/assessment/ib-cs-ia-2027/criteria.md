# IB Computer Science IA 2027 Criteria Reference

This reference is an internal, paraphrased assessment guide for IA Supervisor AI review. It is based on the 2027 IB Computer Science IA syllabus file provided locally by the project owner. It is not a replacement for the official syllabus or teacher judgement.

## Submission Shape

The IA is a computational solution chosen by the student. The submitted solution is assessed through five criteria:

| Criterion | Name | Marks | Recommended documentation length |
| --- | --- | ---: | ---: |
| A | Problem specification | 4 | 300 words |
| B | Planning | 4 | 150 words |
| C | System overview | 6 | 150 words |
| D | Development | 12 | 1,000 words |
| E | Evaluation | 4 | 400 words |
| Total |  | 30 | 2,000 words maximum overall |

The documentation should be one PDF with five separate sections, one for each criterion. The overall documentation word count must not exceed 2,000 words, excluding code excerpts, comments, and diagrams. The solution also includes a video and appendices.

## Key Distinctions

- Solution: the documentation and video submitted by the student.
- Product: the completed software only.
- Documentation: the main IA PDF used as evidence for the five criteria.
- Video: a separate media file showing product functionality and examples of the testing strategy.
- Appendices: a separate PDF containing the full source code and referenced resources. Appendices are not normally used as direct marking evidence, but missing source code can limit full credit for Criterion D.

## Criterion A: Problem Specification

The problem specification is the starting point for the product. It should define a clear problem scenario, measurable solution requirements, appropriate success criteria, and the computational context for the solution.

AI review should check whether:

- The problem scenario is specific and understandable.
- The problem is suitable for a coded computational solution.
- The solution requirements are measurable, not just general intentions.
- Success criteria are derived from the problem requirements.
- The computational context is explained clearly.
- The chosen problem appears complex enough for DP Computer Science IA work.

## Criterion B: Planning

Planning should be consistent with Criterion A. It should decompose the problem into manageable components and present a plan that addresses the success criteria.

AI review should check whether:

- The plan clearly breaks the problem into essential components.
- The decomposition supports later design and development.
- The plan addresses the success criteria from Criterion A.
- The plan includes a sensible chronology for planning, design, development, testing, and evaluation.
- Relevant research, libraries, tools, or dependencies are identified where appropriate.

## Criterion C: System Overview

The system overview should be consistent with Criteria A and B. It should describe the product at a level that helps a third party understand how to recreate it.

AI review should check whether:

- The system model identifies key components.
- Relationships between components are clear.
- The user interface is represented as part of the system model.
- Rules governing component interaction are described.
- Algorithms are identified for relevant components.
- Algorithms are presented in a useful form, such as pseudocode, flowcharts, or clear natural language.
- The testing strategy aligns with the success criteria.
- Proposed tests include suitable data and expected outcomes, especially for incorrect or unexpected inputs.

## Criterion D: Development

Development is the largest criterion. It assesses the product, the implementation of algorithms, the appropriateness of techniques, and the effectiveness of the testing strategy.

AI review should check whether:

- The product functionality is clear and connected to the problem specification.
- The implementation follows the planning and system overview.
- Code excerpts highlight important algorithmic or structural choices.
- Techniques such as data structures, loops, libraries, software tools, or integrations are justified where relevant.
- The student explains or evaluates implementation choices rather than merely listing them.
- Testing covers correctness, reliability, and efficiency.
- The documentation justifies the effectiveness of the testing strategy.
- The video evidence is referenced where functionality or testing is claimed.
- Code excerpts are readable, commented where useful, and linked to the full source code appendix.

## Criterion E: Evaluation

Evaluation should judge how well the product satisfies the success criteria from Criterion A and should justify future improvements.

AI review should check whether:

- The evaluation explicitly returns to the success criteria.
- The student assesses the extent to which each success criterion was met.
- Claims are supported by product behavior, testing evidence, or user/client feedback where available.
- Improvements are realistic and connected to identified weaknesses.
- The student justifies why proposed improvements matter.
